# ダッシュボードの信頼性表示

[English](DASHBOARD_RELIABILITY_INDICATORS.en.md) · [文書の目次](README.md)

ダッシュボードの信頼性表示（S.M.A.R.T.、内部エラー、保持処理とそのペース、簡易チェック）が、取得できる情報のうち何をどう示すかをまとめる。故障の確率を計算するものではない。

## 内部エラーと保持処理を分ける

画面ではFTLの異常counterを「内部エラー」、refresh・padding・read verifyなどのデータ保持の処理を「保持処理」と呼ぶ。サイドバーのページ名は「内部エラーと保持処理」である。

保持処理の主なcounterは、画面では次の表示名で示す。説明はcounterの名前と一般的なNANDの動作から推測したものであり、実機での意味の確認は済んでいない。このため画面の説明も「〜と考えられる」と表示する。研究画面と生データの画面では、照合のため原語を使用する。

| 原語 | 表示名 | 説明（推測） |
| --- | --- | --- |
| Age refresh | 時間の経過による書き直し | 書き込んでから時間が経過したデータを、保持のために書き直した回数 |
| Background refresh moves | バックグラウンドでの移し替え | SSDが自らデータを別の場所へ移動した回数 |
| Bands padded for age | 書きかけ領域を閉じる処理 | 書きかけのまま時間が経過したband（書込み単位の領域）の残りを埋め、閉じたbandの数 |
| Reduced read verify native | TLC読出し検証（reduced） | reducedの意味が未確認のため、説明を付けない |

| 区分 | 入力 | 表示・解釈 |
| --- | --- | --- |
| S.M.A.R.T. | Critical Warning、Available Spareと閾値、Media/Data Errors、総合判定 | 既存のSMART警告条件をカードにも適用。PASSEDでも他項目の警告を優先し、理由をすべて参照できる。FTLの判定と混ぜない |
| FTL異常イベント（内部エラー） | UECC、温度差関連UECC、Host/GCの読出し検証失敗、grown bad blocks、die failures | 比較可能な同系列のcounter増加を表示。一部は障害がすでに観測された情報であり、故障前の警報とは限らない |
| 保持処理 | age/background refresh、band padding、native/pSLC read verify | 増加した項目数と各raw増分を表示。増加のみで故障、refresh不足、ECC余裕不足とは断定しない |
| 保持考慮 | 仮想保管温度・日数、TLC最大P/Eとモデル許容P/E | 仮定上の限界到達を表示。保持試験結果でも、電源OFF中の温度測定でもない |
| 監視保留 | Pfail/Efail、error refresh、open-band read fail、offline blocks | keyとnamed fieldの照合未完了。欠測を0に置換しない |

内部エラーのカードには異常比較の項目数と、増加した保持処理の項目数を表示する。これはイベント件数の合計ではない。異常記録がある場合は「記録」と明示する。情報ボタンでは今回の比較期間とcounter別増分、最後の記録イベントの日時を分離して確認できる。履歴比較ができない場合は「比較待ち」であり、正常としない。比較待ちのときは、カードに理由の短い名前（「研究用keyの対応表が未確認」など）を表示し、理由の全文はマウスを重ねた際の説明に表示する。

研究用keyの意味を実機照合したbuildは25G83である。UECC・読出し検証失敗・grown bad blocks・die failuresのscalar異常counterは、対応表・取得形式が互換で、共有コア連続性レーンに採用された履歴であれば他のbuildでも暫定比較する。カードとイベント履歴には「暫定比較」を表示し、新規イベントには実行build・対応表build・暫定解釈状態をOptionalで保存する。旧イベントの欠測metadataは補完しない。

異常counterの増加量に上限は設けず、大きな増加もイベントとして記録する。counter減少はその項目のみ保留し、Host／NAND／稼働時間のresetや未検証境界は区間の比較を保留する。未知の対応表・異なる取得形式では比較しない。形状不正・重複key・欠測はParserが未取得として扱い、0へ補完しない。histogram・refresh・研究相関は従来の実行build一致条件を維持し、scalar暫定比較へ自動的に広げない。暫定比較は意味の確認済み状態を表さず、別の単調counterへのkey変更を完全には検出できない。

S.M.A.R.T.カードの情報ボタンは全警告理由、総合判定、Critical Warningのraw値、Available Spareと閾値、累積Media/Data Errors、取得日時を表示する。欠測は未取得のままにし、累積エラーを今回の新規エラーとは表示しない。FTLの詳細は「兆候の参考情報 · 故障予測は保留」と明示し、観測可能なcounter増分は表示する。「最新取得値 · raw」を展開すると、UECC、温度差関連UECC、Host TLC/pSLC検証失敗、age/background refreshの取得値を参照できる。故障確率・交換期限・予測TBWへの倍率を新たに作成しない。

ECCの訂正数・訂正可能限界・内部RBERは現時点で取得していない。UECCは訂正不能読出しの情報であり、訂正余裕を測定した情報ではない。Factory bad blocks、Unsafe Shutdowns、PU単独から故障確率を計算しない。

収集間隔、管理者取得経路、対応表・境界の検査、履歴保存、予測倍率は変更しない。OS・firmware・対応表の境界などで比較を保留したときは、既存解析の理由を表示し、境界をまたぐcounterの差分は計算しない。保持処理のペースも比較可能な連続snapshotの組のみから差分を集計する。表示はキャッシュ済み解析のみ参照する。

## 保持処理のペース

バックグラウンドでの移し替え、時間の経過による書き直し、書きかけ領域を閉じる処理、TLC読出し検証（reduced）の回数（書きかけ領域を閉じる処理はbandの数）を、直近14日とその前の最大8週間（56日）で比較する。保持処理は数日に1回まとまって起きるため、直近を7日とすると1回の量の大小で率が大きく変動する。このため直近は14日とする。移し替え・書き直し・書きかけ領域を閉じる処理は稼働時間あたり（稼働24時間を1稼働日として表示）、TLC読出し検証（reduced）はNAND読出し量あたり（100万読出しあたりで表示）に正規化する。比較可能な連続snapshotの組のみを集計し、resetを含む組と、研究セッションと重なる区間は除外する。

「ペース上昇」は次の条件をすべて満たす項目に限る。直近の率が基準の率の2倍以上であること、基準期間を7日ごとに区切った週のうち最も率の高い週の2倍を超えること、観測数と期待数（基準の率で直近の稼働量から見込んだ数）の差が期待数のポアソン雑音の3倍（3√max(期待数, 1)）以上であること。直近の稼働が12時間未満の場合、基準の稼働が48時間未満の場合、12時間以上稼働した週が基準に4週未満の場合は「比較できる履歴が不足」とする。

ペースの上昇は保持処理が増えたことを示すのみであり、故障、データ保持失敗、ECC余裕不足とは判定しない。寿命予測、TBW倍率、収集間隔は変更しない。ダッシュボード上部の「保持処理のペース」カードには状態と、上昇した項目（上昇がなければ通常の範囲にある項目数）を表示する。「内部エラーと保持処理」のページには項目別の直近・基準・比と稼働時間を表示する。

## 簡易チェック

設定の「簡易チェック」で、オフ、毎回の取得時、毎日、毎週から選択する。既定はオフである。有効にした時点で通知の許可を求め、許可されていない場合はそのことを設定画面に表示する。

確認する項目はS.M.A.R.T.のCritical Warning、前回のチェック以降のMedia/Data Errorsとエラーログの増加、前回のチェック以降に記録したFTLイベント、保持処理のペースが上昇した項目である。前回と同じ検出は通知せず、新しい検出のみを通知する。初回のチェックではMedia/Data Errors・エラーログ・FTLイベントは基準として記録し、Critical Warningとペースの上昇のみを検出する。別のドライブに切り替わった場合も、初回と同じく基準を記録し直す。チェックはキャッシュ済みの解析と取得済みの値のみを参照し、SSDから追加の取得は行わない。チェックの記録はアプリの設定に保存する。最終実行時刻と結果は設定画面と、「内部エラーと保持処理」のページにあるペースのカードに表示する。

## 参考基準

固定250 TBではなく、[参考TBW](REFERENCE_TBW.md)のNANDメーカー・世代と論理容量によるresolverを使用する。M1〜M5というSoC名のみではNANDを断定しない。未登録NANDは600 TBW/TBの既定比較と明記する。現在Hostは予測の採用値に統一し、残量は参考総量からその値を引く。Appleの保証値や実使用モデルの下限ではない。

## 検証範囲

参照のモデル／容量別選択、未登録NAND、容量欠測、残量と日付、保持の仮定上の到達、内部エラーと保持処理のラベル、既存FTLのゼロ増分・欠測・reset処理を自動テストで確認する。保持処理のペースは平常・上昇・繁忙週・履歴不足・reset・研究セッション除外の判定を、簡易チェックは初回の基準、重複通知の抑止、他ドライブのcritical warning、実行時期、記録の保存形式を自動テストで確認する。実機の異常発生、データ保持失敗、ECC限界到達を再現する試験は行わない。画面の視認性確認と故障予兆の実機検証は、自動テストやコンパイルとは別である。
