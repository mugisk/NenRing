# 寿命予測の表示用語

2026-10-07。表示名・説明の整理であり、予測モデルの改版ではない。

| 名称 | 行に表示する条件 | 意味 |
| --- | --- | --- |
| 実使用 | 信頼度（該当時） | 現在の損耗とForecast WAFによる推計 |
| 保持考慮 | 信頼度（該当時は横に表示し、以下の条件は下の行へ移動） · 日数 · 温度の出典・温度 · 暫定（該当時） | アイドル実測または指定・既定温度が指定期間続く保持シナリオ |
| クライアント負荷 | WAF 3.5 | 今後のWAFを3.5とした負荷比較。JEDEC試験値ではない |
| 参考基準 | NAND世代・論理容量からのTBW | 同世代市販品の容量比例による比較。未登録NANDは既定値。Apple SSDの公称TBWではない |

旧表示「保持考慮（仮想）非通電365日・30°C」は名称と条件を分ける。
短縮は研究仮定を確定値に変更するものではない。ダッシュボードとメニューバーには保存履歴全体のペースによる到達時期を表示し、「寿命」画面では直近と保存履歴全体のペースを比較する。

## 情報の階層

日本語の `wear` 表記は「損耗」に統一する。「損耗率」はP/EやPercentage Usedから表す寿命消費の指標であり、物理的に擦り減った量やデータ保持能力を直接測定した値ではない。ダッシュボード上部とメニューバーの「損耗」は実使用と同じHost基準の値（累積Host ÷ 予測総Host）で、P/Eから算出するTLC／pSLCの損耗とは計算が異なる。内部の `wear` 識別子と保存形式は変更しない。過去の仕様書・保存済み診断文は原本として維持する。

- 主画面：短い名称、必要な条件、量・日付。既存の列幅・カード高さ・色を維持する。
- 行の情報ボタン：何を比較しているかと、その根拠を簡潔に示す。
- 「寿命予測」横の情報ボタン：比較条件、保持モデルの許容P/E、代替基準の残Host、温度の出典。
- Researchとモデル文書：計算式、係数、転用・外挿・未確認事項。

名称を収めるためにフォントを小さくしない。条件は副次的な文字スタイルで区別し、VoiceOverでも名称と併せて読めるようにする。新しいカードや常時表示の長文は追加しない。

## 変更しないもの

`RetentionScenario.evaluate`、WAF選択、domain予算、予測日付の算出、使用設定、原履歴は変更しない。Clientの通常予測WAFとRetention Researchの独立設定を混同しない。旧ドキュメント内の数式・過去の表示名は履歴の説明として保持する。

2026-10-18追記：保持の計算式を維持し、自動温度の選択をアイドル実測へ更新。実使用・保持考慮の行に観測根拠による信頼度（低・中・高）を表示する。判定規則は[保持の研究推計](RETENTION_RESEARCH_ESTIMATE.md)を参照。従来の「変更しないもの」は2026-10-07の名称整理の範囲を記したもの。

## 公開前の日本語精査（2026-10-08）

S.M.A.R.T.の正常表示は取得した判定の範囲に限定し、「問題はありません」という全面的な保証に読める説明を避ける。Direct FTLの自動取得対象と、実機で取得・解析を確認した範囲も区別する。

実使用の保持補正なし、TLCのみへの保持補正、クライアント負荷のWAFはモデルの仮定として説明する。1500 P/Eは代替基準であり、確認済みの下限とは呼ばない。2026-10-12から参考基準はNAND世代・容量で選択する共通resolverへ接続し、固定250 TB表記は廃止した。

FTL信頼性カードの情報ボタンは比較区間・異常counterの増分・回復活動・比較不能項目と最後の記録イベントを表示する。ゼロ増分と欠測を区別し、回復活動を故障と断定しない。保持比較の許容P/E到達は「仮定上の限界」と表示し、実測の保持障害やSMART異常に昇格させない。カード高さ、収集間隔、予測倍率、イベント保存形式は変更しない。

今回の対象はダッシュボードの案内と、README・現行の予測説明である。過去の設計原本は変更しない。メーカー資料の原典確認、研究画面に残る技術用語の精査、英語UIへの展開は別途行う。

2026-11-13追記：「FTL信頼性」の表示名を「内部エラーと保持処理」に、「回復活動」を「保持処理」に改めた。カード名は「内部エラー」であり、ダッシュボード上部に「保持処理のペース」カードを追加した。上記の記録は当時の名称のまま残す。判定と表示の範囲は[ダッシュボードの信頼性表示](DASHBOARD_RELIABILITY_INDICATORS.md)を参照。
