# メニューバーポップの外観

メニューバーポップは `NSStatusItem` に接続した標準の `NSMenu` で表示する。内容は `NSMenuItem.view` の `NSHostingView` に配置する。角・縁・影・背景のマテリアルはAppKitに任せ、独自の背景、マスク、角丸、影は追加しない。

## 設定の反映

アプリの「表示」設定（`appearanceMode`）をポップにも適用する。

| 設定 | メニューと表示内容 |
|---|---|
| システム | 外観の上書きを解除し、macOSの外観を継承する |
| ライト | 標準のAquaを指定する |
| ダーク | 標準のDark Aquaを指定する |

`MenuBarPopupAppearance` は、メニューと内容のホストに同じ `NSAppearance` を指定する。本文のみを切り替えて背景と不一致になることを防ぐ。公開APIの [`NSAppearanceCustomization`](https://developer.apple.com/documentation/appkit/nsappearancecustomization) を使用し、メニュー用の内部ウィンドウや非公開のビューにはアクセスしない。

起動時とメニューを開く直前に設定を反映する。`UserDefaults.didChangeNotification` も直接監視し、閉じている間も設定を反映する。非表示のSwiftUIビューの設定監視のみでは、変更が次の表示直前まで反映されない場合がある。

開いている間にアプリの外観設定が変更された場合は、通知から共通ランループへ処理を渡し、メニューを閉じる。閉じた後に新しい外観を設定し、次に開く際に全体へ適用する。適用済みの外観と同じ通知では閉じない。再描画のためにメニューやその項目を作り直さない。

これは表示中に `NSMenu.appearance` を変更しても背景のマテリアルが前の外観のまま残り、内容の文字色のみが変更される場合があったためである。設定値や `effectiveAppearance` の一致は、背景の実描画が変更された証明にはならない。

メニューバー上のラベルはmacOSの外観に従う。ポップへの固定指定をラベルに適用し、メニューバーの背景と文字色を不一致にしない。ポップ内のアプリアイコンは、既存のアイコン設定が「自動」の場合に内容の外観へ追従する。

## 検証

`MenuBarAppearanceTests` で、標準メニューとSwiftUIの内容の切替、固定指定の解除、解除後の親の外観への追従を確認する。

実メニューの画像を取得する場合は、次を実行する。検証用ウィンドウが一時的に表示される。

```sh
NENRING_MENU_APPEARANCE_PREVIEW_ROOT="$PWD/build/menu-appearance-preview" \
  scripts/swiftpm.sh test --filter MenuBarAppearanceTests
```

白・黒の検証用背景上で、ライト／ダークの切替による閉鎖・再表示とメニューの高さの増減を記録する。高さの検証には内容の下部に透明な余白を追加する専用の構成を使用する。短期集計を実際にクリックする検証とは区別する。通常のCIでは画面取得をスキップする。

画像は画面の領域を取得する。ビュー単体の描画や、影付き画像を別の背景へ合成した結果のみで、メニューの角・背景・影が正常と判断しない。利用者の履歴を読み込まず、SMART・FTL・リアルタイムI/Oの取得も開始しない。

インストール後は白・暗い背景上で四隅と影を確認し、書込プロセスの件数が変わったときも短期集計と下端の操作ボタンが収まることを確認する。
