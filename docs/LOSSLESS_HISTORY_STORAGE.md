# 計測履歴の可逆集約

[English](LOSSLESS_HISTORY_STORAGE.en.md) · [文書の目次](README.md)

SMART・温度・FTLの標準保存では受理した観測を年齢や件数のみで間引かない。各観測のID、時刻、取得値、欠測、取得条件を保持し、統計へ元の観測列を渡す。

## 保存形式

従来の `history.jsonl`、`temperature-history.jsonl`、`asptool-snapshots.jsonl` は新しい観測の追記用ファイルになる。256観測が蓄積されたら、次の追記の前にブロックへ確定する。確定済みの記録はそれぞれの `<名前>.lossless/` に置く。

- `manifest.json`：形式版、記録型、確定ブロックの一覧。
- `<SHA256>.json.lzfse`：最大256観測の独立した圧縮ブロック。SHA256は展開後の内容を対象にする。

JSONブロックの `nenringHistoryBlock: 1` は旧来の1行1観測と区別するための形式の版番号である。`shared` に全観測で一致するフィールドを一度のみ保存し、`observations` に各観測の残りを保存する。同じ温度やcounterも共通化できるが、観測回数や継続時間の代わりに1点へ減らすことはしない。IDと取得時刻は常に観測ごとに保持する。

値の丸め、時刻の等間隔化、counterの差分のみの保存は行わない。UInt64は整数のまま扱い、新形式のDateは秒未満も保持する。旧ISO8601記録の失われた秒未満は補完しない。

## 書き込み・復旧

通常の追記では過去の全履歴を書き直さない。追記用ファイルが256観測以上になったら、次の観測を追加する前に次の順で確定する。

1. 共通化したブロックを元の型へ復元し、全観測との一致を検証する。
2. 圧縮ファイルを書き込み、再読込み・展開一致・同期を確認する。
3. manifestを原子的に更新して同期する。
4. 追記用ファイルを原子的に空へ置き換える。

3と4の間に中断した場合、ブロックと追記用ファイルの双方に同じIDが残る。読込み時に同じIDを一度のみ採用し、追記用の値を優先する。定期的に旧ブロックを再圧縮する処理はない。

未対応版・切断された行は従来と同じ退避処理で元のbytesを残す。確定ブロックの欠損・ハッシュ不一致・manifest不正は読込みエラーにし、不完全な履歴を完全と見なして新しい保存へ置き換えない。読み込めない間も、新しい観測は追記用ファイルへ保存する。manifestとブロックは変更せず、確定も行わない。寿命予測の再計算は保留する。読み込めるようになると、追記された観測を含めて統合し、次の追記で確定する。

device IDの移行などで履歴全体の置換が必要な場合は、全観測を追記用へ先に保存してから新しいmanifestを確定する。旧ブロックは自動削除しない。

## 旧履歴からの移行

最初の読込みで旧JSONLを `<名前>.pre-lossless-v1.jsonl` にコピーする。旧 `archive/<名前>-*.jsonl[.lzfse]` がある場合は全記録を復元し、現行ファイルとIDで統合する。保管庫の原本は変更しない。読み込んだ記録は新manifestへ保存し、以後は保管庫を繰り返し走査しない。

温度の日別summaryは、元の観測が件数・終点時刻・最小・最大・平均まで一致して復元できた場合のみ解析入力から除外する。元の観測が不足する場合は旧summaryとして残す。summaryから架空の温度列を生成しない。

保管庫の破損は移行エラーとし、原本を残す。既に破棄され、保管庫にもない観測は復元できない。旧版へ戻す際は新形式を読み取れるとは限らないため、アプリを終了し、保存ディレクトリ（`~/Library/Application Support/NenRing/`）全体のバックアップを用意してから移行前の履歴を使用する。バックアップにはJSONLのみでなく、`.lossless/`、設定、証拠ファイル、ジャーナルも含める。

## 解析とメモリ

WAFは元の同一区間の合計Host／NAND差分を使用する。P/Eの段差、reset、firmware・build境界、研究試験除外、reliabilityイベントの時刻範囲は保存形式の集約で変化しない。温度の中央値・時間加重平均・cooldownも元の時系列を使用する。グラフの描画用間引きは保存とは独立する。

通常更新の全体解析と温度更新は分離する。温度は全履歴から過去のFTL区間用の集計表を作成した後、通常は直近35日をメモリへ残す。次のFTL区間を分割できるよう、最後のFTL境界の30分前からも残すため、FTL取得が長期間停止した場合は35日より広くなることがある。古い境界が追加された場合などは保存履歴を読み戻して集計表を再作成する。保存済みの観測を削除する処理ではない。

SMART・FTLの履歴と解析結果には引き続き履歴件数に応じた負荷がある。可逆圧縮で起動時の読込みやメモリ使用量が一定になるわけではない。グラフ用の最近の温度と、過去イベントの温度集計も区別する。

旧サンプリング方針は、旧形式の互換テストなどで明示指定した場合のみ使用する。通常の取得間隔とSSDへのアクセス回数は変更しない。
