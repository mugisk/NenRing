# 寿命予測の読み方

[English](FORECAST_GUIDE.en.md) · [文書の目次](README.md)

NenRingの予測はこれまでの記録と将来の負荷についての仮定に基づいて、書込量を推計したものです。故障日やデータ保持を保証する値ではありません。欠測や短い履歴でも、計算できる範囲を暫定値として表示し、欠測を0に置き換えません。

## 4つの予測

| 表示 | 変えている条件 | 読み方 |
|---|---|---|
| 実使用 | 観測に基づく将来WAF | TLC／pSLCのどちらかが先に目標P/Eへ達するまでの予測。保持補正はかけません。 |
| 保持考慮 | TLCの許容P/E | 低負荷時の実測温度が指定日数続くと仮定した比較。通常は365日です。 |
| クライアント負荷 | 将来WAFを3.5に変更 | 実使用と同じ基準予算で、今後の書込増幅のみを変更した比較。3〜4の範囲も研究上の仮定で、JEDECの要件ではありません。 |
| 参考基準 | NANDプロファイルと論理容量 | 類似NANDの参考値です。Appleの保証値ではなく、250 TB固定でもありません。 |

ダッシュボード上部とメニューバーの「損耗」は実使用と同じ値です。累積Host ÷（累積Host + 残Host）で算出するHost基準の値で、予測WAFやTLC／pSLCの分担率が変化すると残Hostも変化するため、損耗が進んでいても値が下がる場合があります。TLC／pSLCの損耗は平均P/E ÷ 目標P/Eで算出し、Percentage Usedとの比較には先に目標へ達する側のこの値を使用します。FTLによる予測がない間は、NANDの損耗またはPercentage Usedを表示します。

保持考慮の温度は明示的な温度上書きを優先します。自動選択では直近30日から新たに抽出した低負荷区間と、同じdevice・firmware系列の保存済み候補を全期間にわたって組み合わせます。候補がない場合は30°Cを使用します。保存されていなかった過去の区間は含みません。firmware系列はfirmwareの番号の先頭の数字で、591から591.40.3のような小さな更新は同じ系列として扱います。系列が変更された直後でまだ観測がない場合は、更新前の系列の候補を信頼度「低」の暫定値として使用します。自動値の主値は安定・非安定を含む低負荷区間の日別代表温度の中央値です。安定区間のみの中央値と時間加重平均は参考値として確認できます。30°Cは基準条件と観測不足時の既定値です。いずれも電源OFF中に測定した温度ではありません。電源OFF中の温度は測定できないため、実際の非通電時の温度との差は確認できません。

保持考慮はTLCのみを減額する仮定です。現在のTLC最大P/Eを使用し、pSLCの残量とも比較します。温度換算、30°C・365日の基準P/E、保持時間との関係は研究モデルの仮定であり、Appleの保持性能を確認したものではありません。詳しくは[保持の研究推計](RETENTION_RESEARCH_ESTIMATE.md)を参照してください。

低負荷の判定には温度と同時に保存したディスクI/Oの差分を優先します。10分以上・温度5点以上から候補を採用し、取得の空白やカウンタのリセットをまたぎません。I/Oのない旧履歴はSMARTの区間平均で代用し、取得元を区別します。短い候補も表示へ反映しますが、信頼度は件数のみで上げず、観測日数・合計時間・鮮度等で判断します。詳しくは[保持温度の観測規則](RETENTION_RESEARCH_ESTIMATE.md#低負荷温度の観測規則-v3現行)を参照してください。

## 総量・残量・到達時期

FTLの区画境界とgeometryから、TLC／pSLCそれぞれの容量を推定します。容量、現在の平均P/E、Controller EOLからdomainの残りNAND書込量を計算します。中央予測では書込分担率でHost書込量へ換算し、Host換算の残量が小さいdomainの値を採用します。P/Eの刻みはTLCとpSLCで異なるため、僅差の順位から故障を判断することはできません。

```text
domain残NAND = domain容量 × max(0, 目標P/E − 現在平均P/E)
domain残Host = domain残NAND ÷ (将来WAF × domain書込分担率)
予測残Host   = domain残Hostの最小値
予測総Host   = 現在の累積Host + 予測残Host
```

分担率やtopologyが不足する場合は、合算予算や累積損耗による概算へ切り替え、その理由を表示します。domainの容量・分担率は推定であり、実物理配分を独立に測定した値ではありません。

将来WAFの変更は残量の換算にのみ使用します。過去のHost書込量を新しいWAFで再計算しません。参考基準の残量は選択された参考TBWから実際の累積Hostを引き、0を下限とした値です。

到達時期は残Hostを書込ペースで割った予測です。ダッシュボードとメニューバーには保存済みの連続履歴全体のペースによる到達時期を表示します。「寿命」画面では直近と保存履歴全体のペースを比較でき、日付計算に使用する期間も確認できます。直近のペースに使用する期間（通常は30日）の観測が不足する場合は、期間の表示に「*」を付けます。使用するペースの観測が7日未満のあいだは、到達時期に「暫定」を付けます。使用開始日を設定している場合は、保存履歴の観測が7日未満のあいだのみ、使用開始日からの平均ペースを暫定で使用します。この平均は計測前の使用状況を含むため、「寿命」画面の比較列として別に表示します。使用開始日を設定すると、書込ペース欄には「保存履歴」と「使用開始から」の両方を表示します。年数は「20年以上」のような上限で丸めず、計算した値をそのまま表示します。書込ペースのみを最近の値へ変更した日付は、最近のWAFで残量まで再計算した独立シナリオではありません。

ダッシュボードの「直近24時間」には最新のSMART測定から24時間さかのぼって求めたHost書込ペースを表示します。2回の測定が最新の測定から24時間前にあたる時刻をまたぐ場合は、書込量を時間に応じて按分します。観測期間が24時間に満たない場合は暫定値を、比較できる測定値がない場合は「未取得」を表示します。メニューバーの「今日の書込」は当日の累積Host書込量です。

## WAFと書込量の違い

WAFはDirect FTLのNAND書込量とHost書込量の比です。SMARTのHost書込量は別の取得値であり、NAND書込量と合算するものではありません。TLC／pSLCの内訳は容量とP/Eから推定した量で、直接取得した累積NANDとは区別します。

予測WAFは累積比と観測区間の比を対数で混合します。観測Host量とprior相当Host量で重みを決めます。7・30・90日窓はそれぞれ実際に比較できた期間を使用するため、短い履歴では同じ値になる場合もあります。取得間隔の空白、研究試験、更新直後の除外期間は根拠とともに示します。

## 信頼度と警告

低・中・高の信頼度は損耗・WAF・ペースなどの観測実績に対するアプリ内の評価です。的中率や保証確率ではありません。保持考慮には温度の観測実績も関係します。全温度履歴の日数と、実際に採用した低負荷観測の日数は別の値です。

S.M.A.R.T.警告、FTLの内部エラーの増加、保持処理とそのペースは寿命予測と分けて表示します。「取得範囲で新規イベントなし」「取得範囲で異常なし」は全項目正常の証明ではなく、「比較待ち」は正常判定でも異常判定でもありません。重要なデータのバックアップは推計残量や信頼度によらず必要です。

## 入力の確認

「ディスク情報」でSMART・IORegistryの取得値を、「研究」でtopology、残差、区間WAF、温度の由来を確認できます。macOS・firmware・取得経路の変更は連続性検査を通し、未検証の最新raw値と予測へ採用した値を区別します。取得値・推定容量・将来予測の詳しい契約は[NANDモデル](NAND_MODEL_V2_4.md)と[SMART照合](DIRECT_FTL_CROSS_VALIDATION.md)を参照してください。
